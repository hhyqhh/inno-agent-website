# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Marketing + docs site for **Inno Agent** (开源个人学习 Agent). Deployed at `https://inno-agent.dev`. Built with Astro 7 + Starlight + Tailwind v4. The source repo (the agent itself) lives at `https://github.com/hhyqhh/inno-agent`; this repo only builds the website.

## Commands

```bash
npm run dev       # astro dev — local server
npm run build     # astro build — outputs to dist/
npm run preview   # astro preview — serve the built site
```

There is no test runner, no linter, no format command. `tsconfig.json` extends `astro/tsconfigs/strict`.

## Architecture

Two distinct surfaces share one Astro project:

1. **Custom landing page** — `src/pages/index.astro` is a hand-built Tailwind page (NOT a Starlight docs page). It composes `Hero`, `ResearchHighlights`, `Features`, `VideoDemo`, `SkillShowcase`, `Footer` from `src/components/`. Theme toggle and mobile menu are inline `<script>` in `index.astro`. The landing page is Chinese (`lang="zh-CN"`).
2. **Starlight docs** — everything under `src/content/docs/`. Sidebar is **autogenerated** from four top-level directories (see `astro.config.mjs`):
   - `getting-started/` → "快速开始"
   - `tutorials/` → "教程"
   - `skill-library/` → "Skill 库"
   - `use-cases/` → "使用案例"

   Adding a new `.md` file in any of these automatically adds a sidebar entry — no manual nav config needed. Page order within a directory can be set via `sidebar.order` in frontmatter.

### Locale

`defaultLocale: 'root'` with a single root locale `zh-CN`. The `src/content/docs/en/` directory exists but is **empty and unused** — do not add English content there unless you also register an `en` locale in `astro.config.mjs`.

### Starlight overrides

`astro.config.mjs` registers one custom component override:

- `Head: './src/components/HeadWithZoom.astro'` — wraps Starlight's default `Head`, then injects `ImageZoom.astro` (medium-zoom bound to `article img`) and a script that turns `starlight-theme-select` into a click-toggle (instead of a dropdown). The zoom re-inits on `astro:page-load` and tears down on `astro:before-swap` to survive Starlight's SPA navigation.

If you add more Starlight component overrides, register them in the `components: {}` map in `astro.config.mjs`.

### Theming

- Brand color: `#555aff` (light) / `#b7c0ff` (dark). Indigo accent throughout.
- Theme state lives on `<html data-theme="light|dark">` and is persisted in `localStorage` under the key `starlight-theme`. The inline `is:inline` script in `index.astro` runs before paint to avoid FOUC.
- `src/styles/custom.css` is registered via `customCss` in `astro.config.mjs` and contains extensive overrides of Starlight's `--sl-color-*` CSS variables plus custom `--aiecnu-*` variables for the brand lockup and theme-toggle button. Both light and dark variants are defined here. Edit these variables rather than patching component HTML when you want to retheme.

### Tailwind

Tailwind v4 via `@tailwindcss/vite` (not the PostCSS plugin). The `@import 'tailwindcss';` lives at the top of `src/styles/custom.css`. No `tailwind.config.js` — v4 is config-less by default.

## Assets

- `src/assets/` — `logo-light.svg`, `logo-dark.svg` (referenced by `astro.config.mjs` `logo` config).
- `public/images/docs/` — doc screenshots and demo GIFs used by markdown content.
- `public/images/paper/` — research figures (L1/L2/practice-lab/scheduler) used by the landing page.
- `public/videos/` — video assets (currently empty).
- `logo/` — source icon files (`icon.icns`, `icon.iconset`, `icon.svg`, `icon.png`) for the desktop app, not the website.

## Starlight link validator

`starlight-links-validator` is enabled as a Starlight plugin — broken internal links fail the build. When renaming or moving a doc page, update incoming links across `src/content/docs/` and `src/components/` (landing page links to `/getting-started/introduction/` etc.).
